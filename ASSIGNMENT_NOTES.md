# Requirement map and design notes

## C requirements

| Requirement | Where it is implemented |
| --- | --- |
| Player places towers | `DefenseGame.TryPlaceAt`, `Choose` and `HandlePointer`: screen ray intersects the ground, then chooses a marked pad. No towers are preplaced at game start. |
| Towers fire continuously at a fixed rate | `DefenseTower.FixedUpdate`: elapsed-time cooldown from `FireRate`, whenever a live enemy is in range and can be intercepted. |
| Towers aim at an enemy | Turret gimbal rotates toward the calculated launch vector; predictive aiming upgrades direct aiming. |
| Enemies follow predetermined paths | `DefenseRoute` defines the same ordered route every game. Straight sections are joined with quadratic curves to satisfy the B-level improvement. `DefenseEnemy.FixedUpdate` follows it by distance. |
| Game ends when an enemy completes its path | `DefenseEnemy` calls `DefenseGame.EnemyEscaped` at route length; state immediately becomes `Lost`, projectiles are cleared, and the failure screen appears. |

## B requirements

| Requirement | Where it is implemented |
| --- | --- |
| Two tower types with different fire rates, projectile speeds and heights | Pulse and Siege properties in `DefenseTower`; all three required stats differ. Both use real gravity-affected projectiles. |
| Clear placement instructions | Title screen plus persistent command deck: choose 1/2 or a tower button, then click a glowing cyan hex pad. HUD displays costs and the placement limit. |
| Limited tower placement | Six-tower cap, finite starting credits, placement prices, and occupied-pad checks in `DefenseGame.TryPlaceAt`. Selling releases a slot. |
| Paths are not straight | The route turns repeatedly and has sampled quadratic curves at its corners. `DefenseRoute.Position` uses cumulative distance to preserve movement speed around bends. |

## A requirements

| Requirement | Where it is implemented |
| --- | --- |
| Multiple enemy types with different speed and HP | Scout, Runner, Armored and Siege statistics in `DefenseEnemy.Initialize`; distinct silhouettes/colors and health bars help identify them. |
| Non-basic assets | Saved custom polygon meshes in `Assets/Defense/Resources/DefenseMeshes`, generated by `DefenseArt` and baked by `DefenseSceneBuilder`. Drones, platforms, crystal spires, turret hulls and the curved road go beyond unmodified Unity primitives. |
| Predict target location from current position and velocity | `InterceptSolver.TrySolve`, called by `DefenseTower`: solves the time-of-flight equation with the enemy's current velocity and world gravity. |

## Predictive aiming with 3D physics

Let `r = targetPosition - muzzlePosition`, `v` be the enemy's current velocity, `g` be `Physics.gravity`, and `s` be the projectile launch speed. At flight time `t`, the required initial projectile velocity is:

```
launchVelocity = (r + v*t - 0.5*g*t*t) / t
```

The solver finds the earliest positive `t` for which:

```
|r + v*t - 0.5*g*t*t|² = s²*t²
```

It brackets the low-arc solution with short time samples, then refines it with 24 bisection steps. If no reachable solution is found, the tower waits instead of firing a zero or invalid vector. After rotating the barrel, the tower refines the solution from the muzzle's new location.

The shell then flies as a dynamic Rigidbody with gravity and continuous collision detection. It does not home, teleport, or apply damage through a distance check. Only its collision handler applies damage. Target prediction assumes the enemy maintains its current velocity during flight; sudden path turns can cause misses, which is an intentional limitation of the specified prediction model.

## Additional features

- Five escalating waves and a final heavy enemy.
- Earned credits, three tower levels, and 70% sell refunds.
- Target priority favors the enemy farthest along the route.
- Selected-tower range indicator and hover marker for build pads.
- Enemy health bars, projectile trails and impact particles.
- Title, victory, defeat, restart, pause and 2× speed controls.
- Custom neon art, readable tower cards, and a consistent interface.

These are candidates for the open-ended A+ category, not a guarantee of a grade.

## Code organization

`DefenseGame` controls state, economy, waves and player commands. `DefenseTower`, `DefenseEnemy` and `DefenseProjectile` own their respective simulation behavior. `DefenseRoute` and `InterceptSolver` isolate reusable movement and aiming mathematics. `DefenseHUD` builds the interface. `DefenseArt` uses shared materials and meshes. Editor-only build and validation scripts are under `Assets/Defense/Editor` and are excluded from player builds.

The original demo bounced random buggies around an arena and fired at clicked positions. Its scene and scripts remain available for comparison. The assignment game uses a new scene and separate scripts, replacing that demonstration loop with tower placement, route-based enemies, automatic predictive fire, campaign progression, and win/loss states.
